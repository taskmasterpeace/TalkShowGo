# Making LLM Multi-Speaker Dialogue Sound Like Real Human Conversation
## Engineering research for the 3-host AI talk show (researched 2026-08-31)

Context: 3 locked host personalities (model + temperature + system prompt + persona bundle each), reacting to real news with evidence grounding. Current pipeline: one LLM writes the whole script in a single pass. Result: crafted but too clean — complete paragraphs, polite turn-waiting. Goal: heated-podcast feel.

---

## 1. ARCHITECTURE: single-pass vs. actor-per-host loop vs. two-stage

### The verdict from the literature and practitioners
**Nobody who ships natural-sounding multi-speaker audio uses raw single-pass generation.** The field converged in 2025 on either (a) two-stage outline-then-dialogue, (b) multi-agent actor loops, or (c) a hybrid of both. Single-pass survives only where the *charm is the jank* (AI Seinfeld).

### Evidence

**PodAgent (Xiao et al., Mar 2025)** — https://arxiv.org/abs/2503.00455 — the direct head-to-head. A **Host-Guest-Writer multi-agent system**: Host agent plans questions/topics, Guest agents answer in persona, Writer agent assembles/polishes. Result: "significantly surpassing direct GPT-4 generation in topic-discussion dialogue content." Also 87.4% voice-role matching accuracy. This is the cleanest published claim that role-split multi-agent script generation beats one-model-writes-everything.

**MoonCast (Ju et al., Mar 2025)** — https://arxiv.org/abs/2503.14345 — two-stage: (1) content analysis → **briefing document** (title, abstract, main topics, key citations, jargon explanations), (2) LLM turns brief into a script with explicit spontaneity injection (see §2). Key ablation: script text matters almost as much as the TTS. Spontaneity MOS: ground-truth script 4.73, same script with disfluencies stripped 3.21, regenerated spontaneous script 4.03. **The script itself carries ~60-70% of the "sounds real" effect.**

**Dramatron (DeepMind, Mirowski & Mathewson et al., 2022, CHI 2023)** — https://arxiv.org/abs/2209.14958 — the canonical hierarchical (two-stage-plus) architecture: log line → title/characters → **scene beat sheet** → location descriptions → per-scene dialogue, each stage prompted with only the relevant parents. Solves long-range coherence; industry professionals (15 theatre/film pros) validated it as a usable co-writing structure. Lesson for us: beats are planned globally, dialogue is generated locally.

**NotebookLM Audio Overviews (Google, Latent Space interview with Raiza Martin & Usama Bin Shafqat, Oct 2024)** — https://www.latent.space/p/notebooklm — the most-loved AI two-host product. Practitioner lessons:
- They tried both one-model-writes-dialogue and separate-persona-prompts; production is a blend with "a bunch of different things happening under the hood" plus a specialized audio model.
- **Tension is deliberately engineered**: "if there's just too much agreement between people, that's not fun to listen to." They design information withholding ("gradual unrolling"), differing opinions, and tangent-and-return structure.
- Disfluencies are NOT in the transcript — they're generated by the audio model (see §2).
- Humor is never prompted directly; it emerges from format + context.

**AI Seinfeld / "Nothing, Forever" (2023; Max Woolf retrospective Aug 2024)** — https://minimaxir.com/2024/08/ai-seinfeld/ , https://techcrunch.com/2023/02/03/nothing-forever-ai-generated-seinfeld-twitch/ — single-pass "Write a Seinfeld episode" into davinci-003, parsed into characters/lines, Azure TTS, Unity renderer, cloud "director" for cuts. It worked *because* LLM no-planning sequential generation matches improv comedy; hallucination was the comedy. When they swapped models the show died. Lesson: single-pass is viable only when awkwardness is the product. For a competent heated talk show, it's the wrong tool — but their **"director in the cloud" separation (script vs. staging decisions) is a good pattern**.

**Multi-agent conversation frameworks worth reading (open source):**
- **AutoGen GroupChat** (Microsoft) — https://microsoft.github.io/autogen/0.2/docs/topics/groupchat/customized_speaker_selection/ — production-grade orchestrated multi-agent chat: each agent = own system prompt/model; a GroupChatManager picks next speaker (`auto` = selector-LLM, `round_robin`, `random`, or **custom callable** — see §4).
- **Drama Engine (Write with LAIKA, Aug 2024)** — https://github.com/Write-with-LAIKA/drama-engine , https://arxiv.org/abs/2408.11574 — TypeScript framework for narrative agents: "companions" that simulate personalities, **mood systems**, dynamic prompt assembly, delegation to "deputies" (ad-hoc prompt chains, can mix models per companion), automatic context summarizing. Closest open codebase to "3 hosts with personality orchestrated for drama."
- **TinyTroupe (Microsoft, 2025)** — https://github.com/microsoft/TinyTroupe — persona simulation (TinyPersons in TinyWorlds), includes **action-correction mechanisms for persona adherence**; built for believable multi-persona interaction.
- **Murder Mystery Agents (Frontiers in AI, 2025)** — https://www.frontiersin.org/journals/artificial-intelligence/articles/10.3389/frai.2025.1582287/full — full actor-loop architecture with think()/speak() per agent and conversation-analysis-grounded turn allocation (details §4). Their structured loop massively beat naive alternatives on dialogue-breakdown rate.
- **Emergent Mind survey of AI-generated podcasts** — https://www.emergentmind.com/topics/ai-generated-podcasts — surveys the field: role-assignment/persona conditioning + structured outlining ("skeleton-of-thought") + spontaneous-data conditioning are the three recurring architecture moves in 2025 systems.

### Why actor-per-host also fixes persona drift (bonus)
Single-pass generation of a long transcript suffers documented **persona drift / attractor-state collapse** as the context fills with the model's own homogenized output ("Attractor States Emerge in Multi-Turn LLM Conversations," 2026 — https://arxiv.org/pdf/2606.30571 ; overview https://www.emergentmind.com/topics/persona-drift). In an actor loop, every turn is a *fresh call* that re-reads the full persona — drift resets every turn. This is a structural argument for per-host calls independent of the texture argument.

### Architecture bottom line
- **Two-stage is mandatory**: a global beat/outline pass (coherence, narrative craft, planned conflict) feeding a dialogue pass. (Dramatron, MoonCast, PodAgent all do a version of this.)
- **Actor-per-host turn loop for the dialogue pass** is what makes it sound like three people instead of one writer doing three voices — and your existing per-host model+temp+persona bundles map 1:1 onto it.
- A **director/orchestrator** (cheap model or heuristics) allocates turns and injects mid-scene notes; it never writes dialogue.

## 2. CONVERSATIONAL TEXTURE: disfluencies, backchannels, interruptions, incompleteness, drift

### What research says actually moves measured naturalness

**The script must be written in spoken register, not prose.** MoonCast's ablation (above) is the cleanest evidence: stripping fillers/repetitions/informal grammar from a real podcast script dropped spontaneity MOS 4.73→3.21; prompting the LLM to re-inject them recovered to 4.03. Their prompt-level recipe (works via prompting alone, no fine-tune): instruct the model to include **filler words ("um," "uh," "like," "you know," "so"), response words ("yeah," "right," "okay"), repetitions, informal grammar, colloquial expressions**, and formatting tips like commas/spaces inside sentences to force pauses. https://arxiv.org/html/2503.14345

**Disfluency insertion as a dedicated pass works** — "Enhancing Naturalness in LLM-Generated Utterances through Disfluency Insertion" (Dec 2024) — https://arxiv.org/abs/2412.12710 — LoRA-fine-tuned an LLM to insert varied disfluency types into clean utterances, then synthesized with a disfluency-capable TTS. User study: **significantly higher perceived spontaneity, at the cost of slightly reduced intelligibility**. Two design implications: (a) texture can be a *separate cheap post-pass* over clean dialogue rather than burdening the actor prompts; (b) there's a density ceiling — over-inserting hurts comprehension.

**Behavior-conditioned generation** — "Behavior-SD: Behaviorally Aware Spoken Dialogue Generation with LLMs" (Lee, Kim & Kim, NAACL 2025) — https://aclanthology.org/2025.naacl-long.484/ — 100K+ spoken dialogues (2,164 hours) annotated per-speaker for **verbosity, filler frequency, backchannel frequency, interruption habits**, full-duplex (simultaneous contributions). Their BeDLM generates dialogue conditioned on a narrative + per-speaker behavior profiles and wins human evals on naturalness. Even without adopting their model, **the parameterization is the takeaway: make "how much this host fills, backchannels, interrupts, and rambles" an explicit per-host knob** rather than hoping the persona prompt implies it.

**DRIVE** (Jul 2025) — https://arxiv.org/pdf/2507.19867 — synthetic dialog framework whose whole point is disfluency-rich generation (repairs, restarts, hesitations) for in-car assistants; more confirmation that the community treats disfluency injection as its own controllable generation step.

**Where the texture should live — script vs. audio model:**
- NotebookLM: micro-interjections ("Oh really?", "Totally", "uh…", pauses) are **built into the audio model**, not the transcript (Latent Space interview + teardown https://neurlcreators.substack.com/p/how-notebooklm-audio-overview-works). DeepMind's audio stack (SoundStorm/SpearTTS lineage) was trained on "hundreds of thousands of hours" of dialogue to produce them natively (https://deepmind.google/blog/pushing-the-frontiers-of-audio-generation/).
- **SoulX-Podcast (Oct 2025)** — https://arxiv.org/abs/2510.23541 , code https://github.com/Soul-AILab/SoulX-Podcast — open model, interleaved token stream with **explicit paralinguistic tokens** (<|laughter|>, sighs, breathing, throat-clearing; 0.82 recognition accuracy overall, 1.00 for laughter), 90+ minutes stable two-speaker audio. Conditioning the LLM on in-domain spontaneous conversation data is what buys "spontaneity."
- **CoVoMix / CoVoMix2 (Microsoft, NeurIPS 2024 / 2025)** — https://arxiv.org/abs/2404.06690 , https://arxiv.org/abs/2506.00885 — zero-shot **multi-talker mixed-channel** speech: genuinely overlapping speech, backchannels-while-other-talks, laughter, with CoVoMix2 adding precise timing control. This is the research frontier for real overlap.
- **Practical TTS today: ElevenLabs v3 Text-to-Dialogue API** — https://elevenlabs.io/docs/overview/capabilities/text-to-dialogue , https://elevenlabs.io/blog/eleven-v3-audio-tags-bringing-multi-character-dialogue-to-life — takes a **JSON array of speaker turns**, natively handles turn transitions, **interruptions and overlaps**, with inline audio tags: [laughs], [sighs], [whispers], [shouts], [interrupting], [overlapping], [cuts in], [pause]. Since AIOBR already runs ElevenLabs, this is the zero-new-vendor path to rendered interruptions.

### Technique menu (prompt-level → post-process → fine-tune)
| Layer | Technique | Cost | Evidence |
|---|---|---|---|
| Prompt (actor) | Short-turn budget (1–3 sentences default); "react first, then point"; allow fragments; forbid essay cadence | free | PodAgent/MoonCast prompts; NotebookLM tension design |
| Prompt (actor) | Per-host behavior knobs: verbosity, filler rate, backchannel rate, interruption aggression | free | Behavior-SD parameterization |
| Post-pass | Spoken-register rewrite: contractions, false starts on ~10–15% of turns, self-corrections ("wait, no—"), trailing off, mid-sentence restarts | 1 cheap call | MoonCast ablation; 2412.12710 |
| Post-pass | Backchannel weaving: insert short listener lines ("Right right." "Mm." "Come on, man.") from the non-floor hosts | rule-based + tiny call | Behavior-SD; CoVoMix listener behavior |
| Post-pass | Interruption marking: truncate a turn at a clause boundary with "—", next speaker starts with the [interrupting] tag | rule-based | ElevenLabs v3 tags; HANDRAISER (§4) |
| TTS | Audio tags + Text-to-Dialogue rendering; or audio model that adds micro-interjections natively | per-char TTS cost | ElevenLabs v3; NotebookLM; SoulX |
| Fine-tune (later) | LoRA disfluency inserter, or behavior-conditioned dialogue model on real talk-show transcripts | GPU + data | 2412.12710; Behavior-SD |

**Topic drift & callbacks**: no single canonical paper; the practitioner pattern (NotebookLM) is *planned tangents*: the beat sheet explicitly schedules a tangent and the return point ("selective deep-dives that return to main narratives"), plus callback slots filled from show memory (§3). Don't let drift emerge randomly — design it, because LLM actor loops otherwise stay ruthlessly on-topic.

## 3. PERSONA CONSISTENCY across episodes

### The failure mode
**Persona drift** is well documented: prompted personas decay over long contexts; models slide toward a generic assistant voice; multi-turn conversations fall into "attractor states" (https://www.emergentmind.com/topics/persona-drift ; https://arxiv.org/pdf/2606.30571). Zero/few-shot persona prompting "often suffer[s] from role drift and consistency loss in long dialogues" (Persona-Aware Contrastive Learning, ACL Findings 2025 — https://aclanthology.org/2025.findings-acl.1344/).

### What works, at what cost

**1. Character cards done right (cheap, do first).** The role-play literature distinguishes coarse persona (demographics + trait adjectives) from **fine-grained character** (experiences, relationships, speech habits) — the latter is what creates a recognizable voice (survey/resource list: https://github.com/Neph0s/awesome-llm-role-playing-with-persona). A "persona card" measurably improves narrative + dialogue consistency (Customisable Characters framework, 2024 — https://arxiv.org/html/2406.17962v7). Card should contain: identity in 2–3 lines, **stance priors on recurring topics**, lexicon/catchphrases, sentence-length habits, disfluency signature, **relationship map to the other two hosts** (who they needle, who they defend, standing grudges), taboos.

**2. Exemplar transcripts > biography.** The NotebookLM team's hard-won lesson (Latent Space): detailed injected backstories get *over-used* — "the models try to bring it in too much"; personality should show up in *how* they talk, not as recited biography. RoleLLM's method (https://arxiv.org/abs/2310.00746 lineage, see awesome-list above) grounds role imitation in **retrieved verbatim quote exemplars**. Practical: 8–12 verbatim signature lines on the card + **2–4 short example EXCHANGES** (not monologues — you're teaching interaction style, not speech-giving) in each actor prompt. Refresh exemplars occasionally from your own best aired episodes ("self-distillation from approved shows").

**3. Actor-loop architecture itself (free).** Each per-turn call re-reads the persona from position zero — structural drift resistance (§1). The card is *always* fresh; there is no 8,000-token-old persona being forgotten.

**4. Show memory for recurring bits (the cheap realism multiplier for a recurring show).** Continuity across episodes — running jokes, "as I said last week," grudges — is what makes hosts feel like *people with lives*. Architecture from Generative Agents (Park et al., 2023) memory stream: store dated memory items; retrieve by **recency×0.5 + relevance×3 + importance×2** (normalized), inject only top-k (https://agentpatterns.ai/agent-design/generative-agents-memory-stream/). Production-grade options: **Mem0** (https://arxiv.org/pdf/2504.19413), **MIRIX** multi-agent memory (https://arxiv.org/pdf/2507.07957), CAST character-and-scene episodic memory (https://arxiv.org/pdf/2602.06051). For a weekly show you don't need a vector DB: a per-host JSON file — `running_bits[]`, `past_takes[topic]`, `promises[]`, `feuds[]` — curated after each episode (5-minute post-show pass), with the beat sheet pass selecting 2–4 callback candidates per episode.

**5. Per-character fine-tunes/LoRAs (later, only with data).** Standard recipe in the role-play literature: **LoRA rank 8, ~3 epochs** on character dialogue (RoleCraft-GLM https://arxiv.org/pdf/2401.09432 ; OpenCharacter large-scale synthetic persona training https://arxiv.org/html/2501.15427v1 ; personality-indicative data https://arxiv.org/html/2406.18921v2). Worth it only once you have ~50+ approved episodes of a host's transcript; before that, exemplar-grounded prompting on a locked model matches it in practice. Note: a per-host LoRA locks you to a self-hostable base model (the Mac Mini qwen3.5 box could serve 3 host-LoRAs for bulk drafts).

**6. Verification, not just generation.** TinyTroupe ships "action correction mechanisms for persona adherence" — an out-of-character detector that rejects/regenerates a turn. Cheap version: the director validates each turn against the speaker's card ("would X say this? y/n") with a small model, regenerate on fail. Also the **blind voice test** as an offline eval: strip speaker names, have a judge (or Robert) attribute lines; if lines aren't attributable, voices are converging (persona-eval dimensions: conversational ability, persona consistency, behavior consistency, attractiveness — CharacterLLM/RoleLLM eval tradition, survey NAACL 2025 https://aclanthology.org/2025.naacl-long.323.pdf).

## 4. TURN-TAKING: who speaks next

### The one paper to copy
**"Who speaks next? Multi-party AI discussion leveraging the systematics of turn-taking in Murder Mystery games" (Frontiers in AI, 2025)** — https://www.frontiersin.org/journals/artificial-intelligence/articles/10.3389/frai.2025.1582287/full — implements Sacks/Schegloff/Jefferson (1974) conversation-analysis rules for LLM agents:
1. **CSSN (current speaker selects next)**: if the last utterance is the first part of an adjacency pair (question, direct address, challenge), the addressed agent MUST respond next. Detected by an LLM classifier (`detectDesignation()`).
2. **Self-selection**: otherwise every agent runs `think()` — generates private thoughts, decides speak/listen, and outputs an **importance score 0–9** (urgency + relevance to its own goals). Highest score takes the floor; ties random.
- Each agent has 3 memory layers (conversation history, short-term thoughts, long-term facts).
- Results vs. round-robin (EQUAL) and self-selection-only: dialogue breakdowns dropped from 1–8 per 10 utterances to consistently ~1 (p<0.001); best human ratings on coherence/information-sharing.

**This maps directly onto a talk show**: adjacency pairs = "Hold on, Marcus, you really believe that?" forces Marcus next; importance bidding = the host whose lane the topic hits (or who's been quiet, or whose persona is conflict-seeking) grabs open floor.

### Other findings & implementations
- **LLMs are natively bad at this**: they over-interject and can't reliably find transition-relevance places (When2Speak — https://arxiv.org/abs/2605.05626 : 215K examples, 16K conversations of 2–6 speakers labeled SPEAK/SILENT; SFT gives +60% macro-F1 but makes models over-cautious — Missed Intervention Rate 0.50 — fixed with RL asymmetric rewards → recall 0.78–0.81). Takeaway: **don't ask the raw LLM "should you speak?"; run an explicit allocator.**
- **Interruptions as listener-side decisions**: HANDRAISER, "Learning to Interrupt in Language-based Multi-agent Communication" (2026) — https://arxiv.org/abs/2604.06452 — the *listener* predicts the moment to cut in based on estimated value of interrupting; naive LLMs interrupt too early. Scripted-show version: give non-floor hosts an interrupt trigger only when their bid is very high (≥8/9), and cut the current turn mid-clause.
- **AutoGen GroupChat speaker selection** — `auto` (selector-LLM + validator agent), `round_robin`, `random`, or a **custom Python callable** `(last_speaker, groupchat) -> Agent` — the custom callable is exactly where a personality-weighted bidding function plugs in. https://microsoft.github.io/autogen/0.2/docs/topics/groupchat/customized_speaker_selection/
- **RESPOND** (2026, https://arxiv.org/pdf/2603.21682) and adaptive multi-party voice-agent work (https://arxiv.org/html/2606.13544) handle live-audio turn-taking — relevant only if the show ever goes real-time; for offline script generation the Murder-Mystery allocator is sufficient and cheaper.
- A useful bias to add for a *heated* show: **conflict-seeking weights** — raise a host's bid when they disagree with the last speaker's stance (stance distance computable from the beat sheet's per-host stance assignments). None of the papers do this explicitly for entertainment; it's the natural extension of importance bidding, and NotebookLM's "listeners love tension" principle justifies it.

### Practical allocator (synthesis)
```
next_speaker(turn):
  1. detectDesignation(last_turn): addressed/questioned host → they speak (CSSN)
  2. else: bid[h] = w1*topic_affinity(h, current_beat)
               + w2*stance_conflict(h, last_speaker)
               + w3*time_since_spoke(h)
               + w4*persona_aggression(h)
               + noise
  3. bid ≥ INTERRUPT_THRESHOLD while another host mid-turn → interruption event
  4. mid-range losing bids (4–6) → emit backchannel instead of turn
  5. anti-hog: decay bids for 3+ consecutive turns; director can override ("wrap the segment")
```
Weights per host come from the persona bundle — this is where "personality-weighted, topic-driven, conflict-seeking" becomes literal code. Steps 1 can be a cheap classifier call; steps 2–5 are pure heuristics (free).

## 5. EVALUATION: measuring naturalness so you can iterate

### Purpose-built for podcast audio
- **PodEval (Oct 2025)** — https://arxiv.org/abs/2510.00485 , toolkit https://github.com/yujxx/PodEval — open framework, decomposes evaluation into **Text / Speech / Audio** with "Content" vs "Format" emphasis. Ships: Real-Pod dataset of real podcasts as the human-quality reference, objective metrics (DNSMOS, loudness, WER, speaker similarity, timbre difference, speech-music ratio), **dialogue-naturalness listening tests** with spammer detection, MOS questionnaires. Best starting point for a repeatable harness.
- **PodBench (2026)** — https://arxiv.org/html/2601.14903 — benchmark for instruction-aware, audio-oriented podcast *script* generation (evaluates the text stage on its own).
- **Audio MultiChallenge (2025)** — https://arxiv.org/pdf/2512.14865 — multi-turn spoken-dialogue evaluation on natural human interaction.
- MoonCast's 5-axis subjective protocol is the minimal viable human eval: **spontaneity, coherence, intelligibility, quality, similarity**, small rater pool.

### LLM-as-judge, done properly
- **LLM-Rubric (JHU/Microsoft)** — https://www.cs.jhu.edu/~jason/tmp/llm-rubric.pdf — multidimensional rubric scoring **calibrated against human judgments** (a small human-annotated calibration set corrects the judge's biases). The model to copy for "does this sound human" at scale.
- G-Eval-style dimensions in current dialogue papers: **Human-Likeness, Continuity/Context Understanding, Tone and Clarity, Task Appropriateness**; therapeutic-dialogue work adds Naturalness ("conversational authenticity") on 5-pt Likert (StoryMI 2026 — https://arxiv.org/pdf/2605.27393).
- Known judge biases to control (2026 practice): **verbosity bias, self-enhancement bias, surface-fluency bias, emotional overweighting** — require chain-of-thought before scores, randomize order, use a different model family than the generators (https://arxiv.org/pdf/2604.00022).
- **Behavior-adherence metrics** (Behavior-SD): don't just score vibes — measure whether requested behaviors actually appear: fillers per 100 words, backchannels per minute, interruption count, per-host verbosity. Cheap regex/count checks.

### Objective "texture fingerprint" (no humans needed, run every episode)
Compare generated transcript stats against a small corpus of real heated-podcast transcripts (e.g., real battle-rap podcasts — the house has transcripts already):
- turn length distribution (median words/turn; real conversational podcast ≈ 10–25 words, single-pass LLM scripts routinely 40–80)
- speaker share entropy (is one host hogging?)
- interruption rate, backchannel rate, question rate, fragment rate
- type-token ratio / "written-register" markers (e.g., "Moreover," "In conclusion" = fail)
- **blind attribution test**: judge guesses the speaker of shuffled lines; >80% accuracy = distinct voices, ~33% = one writer in three hats.

### The NotebookLM meta-lesson
Formal evals came *after* taste: "critical listening" and dogfooding with a high internal bar moved faster than rater pipelines; then they froze the bar into measurable dimensions (consistency, groundedness, narrative structure) and Likert evals (https://www.latent.space/p/notebooklm). And: "embrace non-determinism" — generate 2–3 candidate episodes and pick, rather than forcing one generation to be perfect. Robert's-ear-first matches how AIOBR already approves narration via ElevenLabs drafts.

## RECOMMENDED ARCHITECTURE for the 3-host show

**Name it like a control room: PREP → BEATS → FLOOR → MIX → MASTER → SCORECARD.** Everything below is buildable now with current APIs; per-host model/temp/persona bundles slot in unchanged.

### Stage 0 — PREP (existing, global)
News item + evidence pack, as today. Add one output: `stance_matrix` — for each story, each host's prior (hot take / skeptic / wildcard), derived from persona cards. Grounding stays here: every claim in the pack gets an id; actor prompts may only assert pack claims (cite-or-cut, house law).

### Stage 1 — BEATS (1 call, global, strong model)
A **showrunner/director model** writes the beat sheet, NOT dialogue (Dramatron/MoonCast pattern):
- 4–7 segments; per segment: the story, the designed **collision** (which two hosts clash, about what), who opens, planned tangent + return point, evidence ids in play, one planned callback pulled from show memory, target beat length.
- Cold-open hook; segment transitions; the episode's verdict/button (titles commit — the show should too).
- Per-segment **information asymmetry**: which host knows/leads with what (NotebookLM's "gradual unrolling"; it manufactures genuine "wait, WHAT?" reactions from the other actors).

### Stage 2 — FLOOR (the actor loop, per-host calls)
Turn-by-turn generation, ~120–180 turns for a 20-min episode:
- **Actor call** = the speaking host's own model+temp+system prompt. Context: persona card (with 8–12 verbatim exemplar lines + 2–4 example exchanges + behavior knobs + relationship map) • current segment's beat card ONLY (not the whole outline — partial info keeps reactions real) • transcript so far (window last ~30 turns + segment summary) • optional director note ("challenge him", "wrap", "bring the callback"). Output: ONE turn, hard budget 1–3 sentences (director can grant "floor" for an occasional rant — variance in turn length is itself texture).
- **Allocator** (code + one tiny classifier call): the Murder-Mystery CSSN-or-SS scheme with a conflict bias —
  1) last turn addressed/questioned someone → they respond;
  2) else bid = topic_affinity + stance_conflict_with_last_speaker + time_since_spoke + persona_aggression + noise; highest bid speaks;
  3) non-floor bid ≥ threshold → **interruption**: current turn is truncated mid-clause with "—", interrupter opens with [interrupting];
  4) mid losing bids → **backchannel line** ("Right right." / "Mmm." / "Nah, come on—") instead of a turn;
  5) anti-hog decay; director ends segment on beat-budget.
- **OOC check** (optional, cheap model): "would {host} say this? y/n" → regenerate on fail (TinyTroupe pattern).
- Model choice: actors can run on fast/cheap models (Haiku-class, or local qwen3.5 for drafts) — persona + exemplars carry the voice; **using a different model family per host adds free voice differentiation** (multi-LLM debate builders do exactly this).

### Stage 3 — MIX (texture pass, 1–2 cheap calls, global)
Spoken-register rewrite over the assembled transcript (MoonCast recipe + 2412.12710 caution):
- contractions everywhere; false starts on ~10–15% of turns; occasional self-correction ("wait, no—", "I mean—"); fragments; trailing offs;
- fillers **per-host-differentiated** (each host has a signature disfluency profile on the card — one says "look, look," another "I mean," another dead-air pauses); enforce a density cap (intelligibility tradeoff is real);
- insert ElevenLabs v3 audio tags: [laughs], [sighs], [exhales], [interrupting], [overlapping], [pause];
- HARD RULE for the pass: it may not change facts, stances, or kill a punchline — texture only. (This pass is a make-it-messier pass; note the inversion — the Codex refute-pass lawyer problem does not exist here, but a "clean it up" instinct in the rewrite model does. Prompt it as a dialect translator, not an editor.)

### Stage 4 — MASTER (render)
**ElevenLabs v3 Text-to-Dialogue API**: JSON speaker-turn array in, multi-speaker audio out with native interruption/overlap handling (https://elevenlabs.io/docs/overview/capabilities/text-to-dialogue). Three locked voices = the three hosts. Fallback: per-line TTS + assembly with slight overlap offsets in Resolve. Watch SoulX-Podcast/CoVoMix2 for open-weight overlap-capable rendering later.

### Stage 5 — SCORECARD (eval, every episode)
- **Objective fingerprint** (script, free): turn-length distribution vs. real-podcast reference, interruption/backchannel/question/fragment rates, speaker share entropy, written-register marker lint, grounding check (every factual line maps to an evidence id).
- **LLM-judge rubric** (1 call, different model family, CoT-before-score): naturalness/spoken register, host distinctness (**blind attribution test**), tension present (was there a real disagreement with stakes?), grounding fidelity, callback landed. 5-pt scales, calibrated occasionally against Robert's rankings (LLM-Rubric method).
- **Robert's ear** stays the release gate (voice-first approval, as with narration). Generate 2 candidate episodes when cheap enough and pick — embrace non-determinism.
- Post-show 5-min memory pass: append new running bits / takes / feuds to per-host show-memory JSON; beat pass reads it next episode.

### Cost picture (per ~20-min episode)
- BEATS: 1 strong-model call (~5–10K tokens) — cents.
- FLOOR: ~150 actor calls × ~3–5K context on cheap models ≈ **$1–3**; allocator mostly free (heuristics + tiny classifier); this is the main new cost vs. single-pass (~$0.10) and it is noise next to TTS.
- MIX + SCORECARD: 3–4 cheap calls — cents.
- TTS dominates total cost regardless of architecture (ElevenLabs per-character pricing), so the script-side upgrade is effectively free in context.
- **Cheaper middle path if the loop feels heavy to start**: keep single-pass-per-SEGMENT drafting from the beat sheet, then a **per-host "line rewrite by owner" pass** — each host's model rewrites only its own lines in its own voice (supported by style-rewrite-with-planning results for low-resource character dialogue, https://arxiv.org/pdf/2603.05933). ~6 calls/segment instead of ~30. Expect it to be better than today but measurably below the full loop on the blind attribution test and interruption realism — it still can't *react*, only re-voice.

### Build order (each step independently shippable, each measurable on the scorecard)
1. Beat-sheet stage + stance matrix (1 day) — fixes "no designed conflict."
2. MIX texture pass + ElevenLabs v3 dialogue rendering (1 day) — biggest audible jump for least work.
3. Actor loop with allocator (2–4 days) — fixes "one writer, three hats"; drops in the existing host bundles.
4. Show memory + callbacks (1 day) — the recurring-show compounding win.
5. Scorecard harness (1 day) — lets every later tweak be A/B'd instead of vibed.
